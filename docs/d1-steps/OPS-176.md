- **Production cutover switch and what is left (OPS-176).** `DB_TARGET` alone no longer moves production: production reads the D1 only when `DB_TARGET` is exactly `d1` **and** a second variable `DB_CUTOVER` is exactly `production-d1` (`PRODUCTION_CUTOVER` in `src/db/target.mjs`; the voice Worker reads the same pair in `voice/src/db/target.ts`). Both are left unset: nothing in the `wrangler.jsonc` files sets `DB_CUTOVER`, and the owner sets it on cutover day. Staging and local runs follow `DB_TARGET` alone, as before. `checks.db` in `/api/health` is judged by the database in use: when the target is `d1` it is `ok` or `error` by a D1 `select 1` (3 second limit, `d1 binding absent` is an error), and Postgres is shown as information (`postgres`: `ok` or `error`) that does not change the status; when the target is Postgres nothing changed. `src/db/postgres-left.json` lists every file that still reaches Postgres (`adapter` = the Postgres half of a store that also has a D1 half, `left` = a direct call that must move first); `src/db/postgres-left.test.ts` fails on a new call site without an entry, prints any stale entry, and prints `Postgres call sites left outside adapters: N`. Delete an entry when its file moves to D1.
