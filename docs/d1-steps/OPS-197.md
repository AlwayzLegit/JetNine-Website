- **The copy tool gains a production target (OPS-197).** `scripts/d1-copy/copy.mjs` takes `--target staging|production` and `--mode load|check|preflight` (`--check` still means `--mode check`). Staging is copied exactly as before: the credential tables stay held back, `users.banned_until` stays NULL, no hash or ban reaches it. Target `production` names the database `jetnine-production` through the top-level wrangler config (no `--env`); `assertTarget` in `map.mjs` accepts exactly the two pairs (staging with `--env staging`, production with none) and refuses every mix, before any call. Production holds back only `request_rate_limits`; it carries the others as stored: the password hash is read as `coalesce(user_credentials.password_hash, auth.users.encrypted_password)` (what `store-pg.ts` reads on sign-in; users with no hash at all are left out), the ban as `auth.users.banned_until`, and sessions, API keys and AI provider keys as they are (hashed or sealed, never opened). A production **load** refuses unless `CONFIRM` is exactly `copy-to-production` and production D1 holds no rows, or `REPLACE` is exactly `replace-production-d1` as well (`assertProductionLoad`); both come from the environment, never from argv. The workflow **D1 copy** has the inputs `confirm` and `replace` and refuses a production target from any ref but `main`. `--mode preflight` reads Postgres, builds the load and runs it against the in-memory D1, prints the preflight line and, for production, `user_credentials: N (N1 set on the site, N2 from auth.users)` and `users banned now: N`, and writes nothing (it needs only `DATABASE_URL`). This row only builds the tool: a production load is the cutover's, on the owner's yes, and nothing here has written to production D1.
